# 主线教材重写设计

## 目标

在保留 MkDocs Material 站点框架、四个 Part 和 Part 4 现有科研方向的前提下，重写教材正文。全书采用“主线教材 + 标签化面试/科研内容”，让读者既能顺序学习，也能围绕面试或科研方向查阅。

## 读者与写作尺度

- Part 1 面向已有大学数学基础的读者，定位为 AI 数学工具箱，不从基础数学重新讲起。
- Part 2 负责深度学习入门、训练基本功和基础面试准备。
- Part 3 负责现代模型、训练范式和进阶面试，不再设置 imitation learning。
- Part 4 保留现有科研方向，提供广覆盖的 Crash Course 和关键工业技术点。
- 行文使用自然、直接的中文，避免固定套话和机械总结。
- 公式服务于理解：关键结论给出必要推导，不堆砌与主线无关的数学细节。
- 章节之间通过前置知识和交叉链接建立联系，不重复完整讲解已有内容。

## 信息架构

### Part 1：AI 数学工具箱

主线包括线性代数、微积分与自动微分、概率统计、优化和几何。Lie 群、傅里叶、图拉普拉斯、PDE、ADMM 等内容可以保留，但作为选修或特定研究方向的前置知识。传统机器学习从 Part 1 移到 Part 2。

### Part 2：深度学习基本功

```text
02-deep-learning/
├── index.md
├── machine-learning-basics/
├── foundations/
├── training/
├── components/
├── architectures/
├── evaluation-debugging/
└── interview-review/
```

Part 2 的学习闭环为：

```text
任务与数据 → 模型与损失 → 反向传播 → 优化与正则化
→ 组件与架构 → 训练诊断 → 评估与推理 → 面试复习
```

具体目录可以在实施计划中根据现有章节调整，但不得破坏这条主线。

### Part 3：现代深度学习方法

```text
03-advanced/
├── representation-learning/
├── modern-architectures/
├── generative-models/
├── post-training/
└── reinforcement-learning/
```

原 Part 3 的 imitation learning 从主线删除。将来如需保留与机器人相关的内容，应放入 Part 4 的具身智能方向。

### Part 4：现有科研方向

保留现有感知、3D 视觉、音频、检索、生成、多模态、MLSys、Agent 和具身智能等目录，不重新划分顶层方向。

每个方向的 `index.md` 同时作为“速览”，包含：

1. 这个方向研究什么；
2. 典型任务及输入输出；
3. 前置知识；
4. 技术路线图；
5. 常用数据集和评价指标；
6. 工业界常见技术点；
7. 当前研究问题；
8. 本部分阅读顺序。

速览只建立地图，具体机制放在子章节中展开。

## 内容角色与元数据

每篇正文使用精简的 YAML 元数据：

```yaml
---
level: basic
roles:
  - core
  - interview
prerequisites:
  - 反向传播
estimated_time: 35min
status: planned
---
```

角色只有三种：

- `core`：主线必读；
- `interview`：面试重点；
- `research`：科研方向和论文阅读重点。

## 章节写法

章节优先围绕一个清晰问题展开：先建立直觉，再解释机制和必要公式，最后给出工程、面试或科研上的应用。章节不强制使用完全相同的标题，以免形成模板化文风，但应覆盖以下内容中与主题相关的部分：

- 问题背景与直觉；
- 概念、机制和关键推导；
- 一个具体例子或最小实验；
- 常见误解和适用边界；
- 面试辨析、工程问题或科研延伸；
- 与前后章节的关系。

## 资料与引用

编写章节前先查看全书目录、所在目录的 `index.md`、前置章节和相邻章节。可以使用知乎和公开高质量博客寻找解释角度、常见误区和工程经验，但公式、技术结论及前沿方法必须用教材、论文或官方文档交叉验证。

资料记录在根目录 `reference.md`，按 Part 和主题维护，避免把项目决策混入参考资料。

## 重写与版本策略

1. 将重写前的分支和未提交内容完整归档；
2. 从本地 `main` 创建独立重写分支；
3. 先搭建目录、元数据、导航和校验基础；
4. 按目录重写 Part 2，每个目录单独验证和提交；
5. 完成 Part 2 后执行严格构建、链接和内容检查；
6. 审核通过后合并到 `main` 并推送，由 GitHub Actions 发布。

清空正文不等于立即删除历史内容。归档分支始终作为恢复来源，重写分支只保留新的目录骨架和已完成正文。

## Part 2 完成标准

- 新目录与 `mkdocs.yml` 导航一致；
- 每篇正文包含有效元数据、明确前置知识和内容角色；
- 主线从传统机器学习桥梁贯通到训练、架构、诊断和复习；
- 面试内容解释原理和取舍，不写成孤立题库；
- 章节间没有大段重复，交叉引用可以正常跳转；
- 所有内部链接有效，`mkdocs build --strict` 通过；
- 每个目录有独立 Git 提交，最终可以安全合并到 `main`。
